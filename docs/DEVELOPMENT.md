# Разработка: как устроен пакет `samsung.wgt`

Приложение Lampa для телевизоров Samsung, собранное на основе пакета byskaz (`lampa.byskaz.ru/samsung.wgt`)
и доработанное под реальную работу на ТВ: автообновление, автовыбор серверов Skaz, сторож плеера,
плеер Tizen (AVPlay), таймер сна, цветные кнопки.

Сама Lampa в пакете **не правится**: это сборка с сервера byskaz, а пакет — загрузчик и набор модулей вокруг неё.
Если сборка на сервере совпадает со встроенной (hash), Lampa запускается из пакета; новее — качается с сервера;
сервер недоступен — тоже встроенная копия.

| | |
|---|---|
| ID приложения | `0SG81L944p.Lampa` (тот же, что у пакета byskaz — ставится поверх) |
| Версия пакета | `src/config.xml` → `<widget version>`; история — [CHANGELOG.md](../CHANGELOG.md) |
| Целевой ТВ | Samsung 2022 (Tizen 6.5, браузер на Chromium 85) |
| Сервер Lampa | `http://lampa.byskaz.ru/lampa-main/` (Lampa + патч byskaz) |
| Установка | установщик на телефоне (подписывает сам) или Tizen Studio с сертификатом Samsung — см. «Установка» |
| Проверка | автотесты `tests/run.cjs` (437), Chromium 85, официальный эмулятор Samsung TV 10.0 — см. «Эмулятор» |

## Как это работает

### Запуск (порядок скриптов в `src/index.html`)
1. `$WEBAPIS/webapis/webapis.js` — API Samsung. Без него Lampa не видит Tizen и не включает AVPlay.
2. `polyfills.js` — совместимость и защиты: недостающие функции старых браузеров, безопасный `registerKey`,
   User-Agent для AVPlay, таймаут открытия IndexedDB.
3. jQuery и прочие библиотеки Lampa (`vender/`).
4. `skazauto.js`, `playerguard.js`, `bsfeatures.js` — наши модули (объявляются, стартуют после готовности Lampa;
   сетевые перехваты `bsfeatures.js` ставятся сразу).
5. `loader.js` — загрузчик:
   - ставит настройки по умолчанию (один раз): меню всегда, «ТВ by Skaz», плеер Tizen;
   - пишет стартовые настройки byskaz (как lampainit.js), чтобы не было перезагрузки при первом запуске;
   - параллельно: быстрый замер серверов Skaz (старт по первому ответу текущих, не позже 2,5 с) и проверка связи
     `assembly.json` (таймаут 3 с, повторы в течение 15 с — обычно 4–5 попыток);
   - hash сборки совпал со встроенной — `app.js` из пакета (`local`), иначе `app.min.js` с сервера; ошибка, «загрузился,
     но это не Lampa» (заглушка провайдера) или 30 с без загрузки — встроенный `app.js` (`bundled`);
   - сборку с сервера скачать не вышло — её hash запоминается (`bs_failed_hash`), и автообновление 30 мин не
     перезапускает ради неё (иначе перезапуск каждые полминуты);
   - показывает строку статуса и этап Lampa, ошибки — красным;
   - после готовности Lampa запускает модули, раздел настроек и автообновление.
6. `http://lampa.byskaz.ru/lampainit.js` — стартовые настройки byskaz; он же подгружает `privateinit.js`
   (плагины Skaz). Сам он при первом запуске перезагружает страницу — загрузчик это предупреждает (см. выше).

### Автообновление (`loader.js`)
- Tizen **не перезапускает** приложение: по Home держит его в памяти (`prelaunch` + `reload="disable"`).
  Поэтому сервер проверяется каждые 30 минут и при каждом возврате в приложение (не чаще раза в 5 минут).
- Сравнивается `hash` из `assembly.json` с hash запущенной сборки. Есть новая — уведомление и перезапуск через 5 с;
  во время фильма — после закрытия плеера.
- Плагины byskaz/Skaz запрашиваются с меткой суток `_bs=` (+ `bs_plugins_salt` после «Проверить и обновить»,
  `bsfeatures.js`), иначе ТВ мог держать их в кэше неделями.

### Серверы Skaz (`skazauto.js`)
- Домен контента `skaz_domain`: `skaz.tv`, `skaztv.online`, `skaz.team`, `skaztv.top`, `list.skaz.tv`
  (список перечитывается из `privateinit.js`). Проверка — `favicon.ico` с типом image/*.
- Серверы источников `skazonline_servers`: прямые `online3/4/5/7.skaz.tv` или Cloudflare `onlinecf3/4/5/7`.
  Проверка — `/version` отдаёт число.
- 4 замера: медиана, джиттер, потери. Оценка = медиана + 2·джиттер + 1500·потери.
- Мёртвый (потери ≥ 50%) — смена сразу (перезапуск после плеера); хуже на 40% и 150 мс или джиттер > 150 мс —
  со следующего запуска. Через 20 с после старта, потом каждые 3 минуты и при появлении сети.

### Сторож плеера (`playerguard.js`)
- Следит за временем воспроизведения (события `Lampa.PlayerVideo.listener`, одинаковы для AVPlay и встроенного).
- Зависание: не стартовало за 25 с (`START_LIMIT`), встало > 20 с, или после ошибки видео не пошло за 6 с
  (`ERROR_GRACE`). Пауза/перемотка/свёрнутое приложение не считаются.
- Ошибки AVPlay берутся у самого AVPlay (обёртки `setListener` → onerror и `prepareAsync`): Lampa их до
  `PlayerVideo 'error'` не доносит. Там же считаются остановки на подгрузку (`onbufferingstart` после старта) —
  `BSGuard.stalls()` нужен замеру скорости.
- Действия: (видео уже шло) тот же поток с той же секунды → качество ниже → … → «Источник не отвечает», закрытие
  плеера через 4 с (отменяется, если видео пошло).
- Подгрузка буфера (`PlayerVideo 'progress'`, `down: 'NN%'`) с растущим % — не простой, до `BUFFER_GRACE` 60 с подряд.
- Обрыв сети (`offline`): простой не считается; `online` — тот же поток с той же секунды.
  ТВ-канал — одно переподключение. Торренты не трогает.

### Плеер (`bsplayer.js`)
- **Метки пропуска** — `https://skaz.team/report.php?segments=<tmdb>&season=&episode=&duration=<сек>&chapters=1&type=`
  (зеркала `list.skaz.tv`, `skaztv.online`; CORS `*`). Народные метки отдаются только при длительности ±2 с, проверенные
  («season»: true) — при любой. Поэтому запрос — после первого `timeupdate` с длительностью. Метки Skaz `intro/credits/recap`
  → `skip`, `ad` → `ad` и отдаются **родному модулю меток Lampa**: он не выведен в `Lampa.*` и читает `data.segments` только
  на старте, поэтому вызываем ровно его обработчик из `Lampa.Player.listener._listeners.start` (узнаётся по `data.segments`).
  Lampa сама рисует кнопку, отметки на шкале, автопропуск (`player_segments_skip/ad`, по умолчанию `auto`) и «Следующая
  серия» на титрах.
- **Главы** — тот же ответ (`chapters`, привязаны к фильму, не к длительности). Кнопка «Главы» в панели плеера.
- **Ночной режим** — чёрный слой внутри `Lampa.PlayerVideo.render()` (поверх видео, под панелью), `bs_night` = 0/30/50/70.
- **Дорожка сериала** — `bs_track_<tmdb>` = `{index, lang}`; текущая — `webapis.avplay.getCurrentStreamInfo()` (у AVPlay
  `enabled` только на запись) или `selected/enabled` встроенного плеера.
- **Буфер AVPlay** — `bs_buffer` (`balanced` 4 и 8 с — по умолчанию / `fast` 2 и 6 с / `reliable` 8 и 15 с / `auto` —
  как у Samsung, 10 с), ставится в обёртке `open()` (`polyfills.js`): `setBufferingParam` принимается только между
  `open` и `prepare`. Почему 4 с: HLS у источников Skaz режется кусками по 6 с — при буфере Samsung (10 с) до первого
  кадра качаются два куска (1080p ~9 МБ), при 4 с — один.
- **Скорость канала** — `bs_bw` = `{bps, n, at}`: медиана последних 12 замеров `getStreamingProperty('CURRENT_BANDWIDTH')`
  (раз в 15 с во время просмотра, `bsplayer.js`). `bsfix.js` оборачивает `Lampa.Player.play`: если качество, которое
  Lampa поставила бы (`video_quality_default`, у byskaz 2160), не помещается в 70 % замеренной скорости — старт в
  посильном (номиналы: 2160 — 16, 1440 — 10, 1080 — 5, 720 — 3,5, 480 — 1,6 Мбит/с). На время синхронного вызова
  `play` подменяется `Storage.field('video_quality_default')`, настройка не меняется. То же для выбора в плейлисте
  плеера (`PlayerPlaylist.listener.send('select')` — следующая серия идёт во внутренний `play` мимо `Player.play`).
  Замер старше недели, без `v:2` или меньше 3 замеров не берётся; выключатель — `bs_bw_quality`.
  **Ловушка:** у MP4 при полном буфере `CURRENT_BANDWIDTH` ≈ битрейт видео, а не канал. Замер ниже битрейта текущего
  качества ×1,5 берётся, только если были остановки на подгрузку (`BSGuard.stalls()`, по `onbufferingstart`).
- **Ошибки AVPlay** Lampa не пересылает (обработчик 'error' читает `video.error`, у обёртки AVPlay его нет) —
  `playerguard.js` оборачивает `webapis.avplay.setListener` (onerror) и `prepareAsync` (колбэк ошибки).
- **Отладка на эмуляторе:** `python tools/pack.py --debug 10.0.2.2` (10.0.2.2 — ПК из эмулятора) и `tools/debug/logserver.py`;
  журнал консоли приходит на ПК. Экран — `ecp-cli` не снимает (GL), только окно эмулятора.

### Источники с RCH (`bsrch.js`)
- Часть источников отвечает `{rch:true, nws:...}`: плагин Skaz открывает
  `NativeWsClient` (WebSocket, `ws://online*.skaz.tv/nws`), ждёт `Connected` → `RchRegistry` → ответ `RchRegistry` и
  повторяет запрос. В `onlines.js` у этого пути **нет таймаута и обработки ошибки** (`autoReconnect:false`): сокет не открылся
  или сервер молчит — список крутится вечно, а при выборе видео висит `Lampa.Loading`. В APK этого нет — сервер сразу даёт
  ошибку и плагин переходит к следующему источнику.
- Перехват присвоения `window.NativeWsClient` (defineProperty) и обёртка `connect/_emit/close`: 8 с на `Connected` (один
  повтор новым сокетом), 8 с на ответ регистрации; закрытие сокета до регистрации — сразу повтор/ошибка. После сбоя 3 мин
  ждём вдвое меньше и без повтора.
- Ошибка: если висит `Lampa.Loading` (ждали ссылку) — снимаем её и уведомление; иначе штатный
  `component.doesNotAnswer({timeout:true})` — плагин сам пишет «Источник не ответил» и переходит к следующему.
  Ничего не делаем, если экран уже сменился (счётчик вызовов `uiDraw/uiNote/empty/request/...` компонента) или плагин
  бросил этот сокет ради другого (его нет в `window.nwsClient`).
- Клиент `nws-client-es5.js` грузим заранее с online3, затем 4/5/7 (у плагина адрес жёстко online3, ошибка не обрабатывается);
  `putScript` этого файла тоже идёт через наш загрузчик.
- Проверено: `tests/run.cjs` (проверки RCH) и связка «настоящий nws-client + rchInvoke/Registry из onlines.js + bsrch.js»
  в Node с настоящим WebSocket: живой online3 — без вмешательства; мёртвый порт — сразу; молчащий сервер — ~16 с.

### Автоподбор источника (1.6.5, `bsfix.js` + `playerguard.js`)
- Что играет: `remember(comp, file)` при выдаче ссылки (`getFileUrl` → json.url): сезон, серия, имя (активный
  `.skaz-chip--active`), balanser.
- Сторож: не стартовало (`!s.played`) → сразу `giveUp(…, BSFix.autoNext)`; шло и встало → прежние шаги, в конце autoNext.
- `autoNext`: `c.nextSource()` (рейтинг плагина), не больше 3 подряд и без повторов; сезон — `c.seasonMemory(номер)`
  (плагин сам выберет сезон с этим номером в любом источнике), озвучка — `voice_name`, как в changeBalanser;
  `c.switchSource(next)`. Обёртка `uiDraw` (`autoPick`): та же серия (episode, season) → `params.onEnter(item)`.
- Значок источника: `bsplayer.js` begin → кнопка `src` в панели, `BSFix.openSources()` (закрыть плеер → `uiSourceMenu`).
  С 1.7.9 только при `bs_src_badge` (по умолчанию выкл.): источник подбирается сам.

### Проверка источников (`bsprobe.js`)
- `check(url)`: GET потока (видео — до заголовков, m3u8 — целиком). 404/410/5xx → `dead`; 200/206 (m3u8 — с `#EXTM3U`)
  → `ok`; остальное (403, 0, таймаут 6 с) → `unknown`: CDN отказывают странице (Origin: null), а AVPlay играет.
  Сторож (`playerguard.js` `quickCheck`) на `dead` до первого кадра — `escalate` сразу, не через START_LIMIT.
- `race(comp, exclude, want)`: 3 кандидата (`skaz_sources` фильма, порядок `comp.sourceOrder`, без пустых по
  `comp.sourceState` и плохих по нашим итогам) параллельно: `comp.requestParams(url)` → lite-ответ
  (`.videos__item`/`.videos__button`, `data-json`) → `decide`: сезон → папка → озвучка `voice_name` → серия →
  `call` за ссылкой → `check`. Первый `ok` — победитель; к сроку 14 с — выдавший ссылку (`unknown`); RCH — `skip`.
  Не больше 6 шагов на источник, таймаут запроса 7 с.
- Итоги на фильм — 10 минут (`ok`/`dead`/`nolink`/`missing`/`failed`). `bsfix.js`: `autoNext` → гонка → `switchTo`
  (как раньше: память сезона, озвучка, `switchSource`, `autoPick`); не больше 3 переключений. Обёртка `nextSource`
  плагина: сначала проверенный `ok`, плохой — первый неплохой кандидат.
- Переключатель `bs_race` (вкл.). Итог гонки — строка в «Журнале запросов источников».

### Продолжить с места (`bscontinue.js`)
- Память `bs_resume` (до 20, свежие сверху): карточка (только нужные поля), сезон, серия, позиция, длительность, `done`.
  Пишется раз в 15 с, на смене серии и на закрытии — только для видео из Skaz (`BSFix.current()`). Досмотренный (>92 %)
  фильм уходит; включили и закрыли за 30 с — прежняя запись не теряется.
- Своего ряда на главной нет с 1.7.12 (дублировал родной «Продолжить просмотр» Lampa). Продолжение — плитками Smart Hub.
- Продолжить: `want` → `Activity.push('full')`; на `full`/`complite` — `hover:enter` по `.lampac--button` (до 12 попыток).
  Метку в карточке не донести: Lampa подменяет `object.card` полными данными TMDB до `complite`.
  Сериал: плагин сам ставит источник/сезон/озвучку из `online_watched_last`; в его `Activity.push('lampacskaz')` добавляем
  `lampac_continue_episode` (досмотренная — +1; только если плагин помнит сезон). Фильм: `BSFix` зовёт `onDraw` из `uiDraw`,
  включаем `comp.uiPickResume(items)` через `params.onEnter`. Позицию восстанавливает таймлайн Lampa.
- Smart Hub — `bshub.js` (ниже); отсюда `hubItems()`. Нажатие плитки (`bs_resume` в карточке): `start_deep_link`
  (опрос до готовности) или `Activity.push` → `noteResume`.
- Новые серии: `tv/{id}` TMDB раз в 12 ч для досмотренных сериалов, `last_episode_to_air` новее и не старше 21 дня →
  `news`, уведомление один раз (`bs_news_noted`).

### Панель Smart Hub (`bshub.js`)
- **С 1.7.42 службы превью в пакете нет** (`config.xml`: ни `tizen:service`, ни `use.preview`), а первый скрипт
  `index.html` не даёт Lampa запустить её (`launchAppControl` с `pick`/`ForegroundApp` отбрасывается). Причина: значок
  Lampa на главном экране заменялся серой заглушкой и при `bs_hub_mode=off` — службу запускал сам ТВ (`bg_service`), а
  Lampa с сервера успевала отправить ряд раньше, чем загружался перехват в `bshub.js`. Описание ниже — история.
- Одна панель на приложение (Preview API); ТВ 2022+ склеивает разделы в один ряд без их названий — раздел пишем в
  подпись плитки («Турецкий сериал · 2025», «Популярное · 2026»).
- Обёртка `tizen.application.launchAppControl`: данные `ForegroundApp` от Lampa только запоминаются (`lastPick`), службе
  уходит `send()`. `rewrite(lastPick, hubItems, турецкие, кадры)`: Lampa — уведомления `position 0`, «Продолжить» 1,
  популярное 2. Порядок: наш «Продолжить с места» (`bs: 1`, `is_playable`; пусто — Lampa), уведомления, турецкие
  (`bs: 2`, TMDB discover как у кнопки, раз в 12 ч, `bs_hub_turk`, вместе с `bs_menu_turk`), популярное (8). Все плитки
  `16by9`, `http://imagetmdb.com/t/p/w780` + кадр; без кадра выпадают (кроме нашего ряда).
- Не чаще раза в 10 минут (требование Samsung к `setPreviewData`): `request()` → таймер до `bs_hub_sent + 10 мин`;
  ждёт готовности Lampa (до минуты), узнаёт турецкие и недостающие кадры (до 20 с) и отправляет один раз.
- Кадр: TMDB `{tv|movie}/{id}/images?include_image_language=ru,en,<язык оригинала>,null` → backdrop с языком ru, en,
  оригинала (ширина ≥ 780, по оценке), иначе `backdrop_path`. Кэш `bs_hub_art` ({`tv:id`: {p, t}}, до 300, 30 дней);
  новые кадры — очередью до отправки.
- `request()` зовут: ряды Lampa (раз в 10 мин), закрытие плеера (`bscontinue.js`), запуск пакета.
- **С 1.7.13 по умолчанию `off`**: ряд обновляет только фоновая служба (`webapis.preview` в приложении нет — эмулятор),
  а запущенная служба (скрытое приложение пакета, `show=false`, значок у неё есть) для ТВ становится последним
  приложением: в ряду недавних вкладки «Узнать» вместо значка Lampa — серая заглушка (проверено на ТВ: с `off`
  значок держится). `getAppsUsageInfo` — Permission denied; запуск самого себя после службы перезапускает Lampa
  по кругу (не делать).
- `bs_hub_mode`: `posters` (наши разделы в форме данных Lampa — 1by1, постер w300 с того же
  адреса, `is_playable: false`, без своих полей, не больше 3 разделов), `wide` (широкие кадры), `lampa` (данные Lampa
  как есть), `off`. ТВ 2022: с `wide` значок Lampa на главном экране после запуска заменялся серой заглушкой, с данными
  Lampa — нет; что именно мешало (16:9, большие картинки, `is_playable`, поле `bs`, 4 раздела) — не выяснено.
- С 1.7.11 ряды уходят сразу в момент, когда их шлёт Lampa (на старте и раз в 10 мин), как в оригинале; чего не хватило —
  в фоне (`refreshLater`). Ограничение 10 минут — только на свои внеочередные отправки (`request`).
  Для проверки на ТВ: значок Lampa на главном экране пропадает после запуска приложения (1.7.3, ТВ 2022) — из-за
  ряда превью или нет.
- `appcontrol` с `PAYLOAD` при открытом плеере → `Player.close()` до обработчика Lampa (слушатель ставится при загрузке
  файла): иначе Lampa открывала карточку под плеером, и на экране оставался прежний фильм.

### Удобства просмотра (`bswatch.js`)

### Telegram-бот (`src/bstg.js`)

Бот работает **внутри Lampa на ТВ**: своего сервера нет. Поэтому, пока Lampa на ТВ не открыта,
бот не отвечает — это известное ограничение, его видно пользователю в описании.

**Кто есть кто.** Владелец — чат в `bs_tg_chat`. Гости — в `bs_tg_users` (`active()` — подключён,
не отключён и не ждёт одобрения). `allowed(c)` решает, допускать ли сообщение; `as(c, fn)` выполняет
код от имени чата `c`; `isOwner()` — проверка владельца. Ответ гостю всегда идёт через `as(гость, …)`.

**Одобрение новых людей** (`bs_tg_approve`, по умолчанию вкл.). Новый человек по приглашению из QR
становится `pending` и не проходит `allowed`/`active`. Владелец получает «✅ Разрешить / 🚫 Отклонить»
(`ok:` / `ku:`). Повторный запрос от того же человека владельцу — не чаще раза в час.

**Приглашение** — `inviteCode()`: хэш токена с солью `bs_tg_invite_salt`. «Сменить приглашение» меняет соль:
старый QR и пересланные ссылки перестают подключать, уже подключённые остаются.

**Гости и видео** (`bs_tg_guest_play`, по умолчанию вкл.). Выключено — гость может искать, подписываться и
вести списки, но не открывает видео на ТВ (`o`, `v`, `d`, `D` в `searchAction`/`handleIn`).

**Настройки владельца общие для всех ТВ.** Одобрение, видео гостей и соль приглашения ходят по каналу
(`cfgSend` / `onCfg`): новый ТВ при `ask` получает их от главного.

**Канал между ТВ** — ntfy.sh, тема из токена (`busTopic`). Сообщения запечатаны `Crypt.seal`:
поток HMAC-SHA256 по счётчику и тег 16 байт, формат `{z:2, n, c, s}` (base64). Ключ
`Crypt.key('lampa-bus-v2|' + токен)`. `busOpen` отбрасывает повтор nonce, сообщения старше 24 ч и
всё незашифрованное — кроме `hello`/`bye` от старой версии (без чата и команд).

**Подключение телефона.** QR содержит `#тема.секрет`; страница `docs/pair.html` шифрует токен секретом
`lampa-pair-v2|…`. Второй ТВ подключается кодом из 8 цифр (ключ `lampa-join-v2|код`).

**«⌨️ Набрать на ТВ»** (`typeStart` / `typeSend`, команда `/type`). Текст очищается от разметки
(`typedText`: Lampa вставляет его как HTML), открывает поиск через `Lampa.Search.open({ input })`.
Во время видео не открывает. Другой ТВ получает текст по каналу (`t: 'type'`) и подтверждает (`ack`).

**Меню и команды.** `menuRows()` — кнопки, `KB` — постоянная клавиатура, `COMMANDS` — список команд
(`setMyCommands`). Разовая рассылка «что нового» идёт по `bs_tg_cmds` (сейчас `'8'`); меняя значение,
рассылка повторяется.

**Что проверять.** Блок «bstg.js» в `tests/run.cjs`: шифрование и подпись сообщений, открытие канала,
подключение телефона и второго ТВ, одобрение, гости и видео, `typedText`/`typeHere`. Любое изменение
протокола канала — сначала тест на подделку, повтор и старое сообщение.

## Что важно знать об экосистеме byskaz/Lampa
- **Origin: null.** Пакет открыт как `file://`, все запросы страницы уходят с `Origin: null`, многие балансеры/CDN
  такие отклоняют. Lampa BS для ПК вырезает этот заголовок; на ТВ так нельзя — поэтому видео отдаём в AVPlay
  (он ходит сам, без Origin) и не даём Lampa качать плейлист страницей.
- **RCH.** Онлайн-плагин Skaz (`skaz.tv/onlines.js`) просит телевизор самому скачивать страницы источников. Часть
  «висящих» источников — это они (запросы тоже с `Origin: null`). Пакетом это не лечится.
- **Реклама.** Сборка byskaz показывает рекламу (`skaz.tv/vast`, `bid.ctv.house`) с паузой между показами.
- **Передача на другое устройство** — штатная функция Lampa через сокет CUB; нужен один аккаунт CUB, не одна сеть.
- **`tv.js` без параметров** отдаёт заглушку 104 байта; плагин запрашивает его с параметрами — это нормально.

## Правила разработки
1. **Lampa и плагины byskaz не правим.** Только перехваты и настройки вокруг них. Всё, что мы делаем, должно
   выключаться переключателем или не влиять на работу Lampa, если отключено.
2. **ES5.** Никаких `let/const`, стрелок, шаблонных строк, `async` — старые ТВ. Проверка:
   `npx acorn@8 --ecma5 --silent файл.js`.
3. **Всё, что мы делаем, видно пользователю**: уведомление о переключении сервера, обновлении, действии сторожа.
4. **Не мешать просмотру**: перезапуски Lampa — только когда плеер закрыт.
5. **Каждая новая сборка — новая версия** (`pack.py --bump`) и запись в CHANGELOG. `pack.py` не даст выпустить
   уже выпущенную версию с другим содержимым.
6. **Проверять на движке ТВ** (Chromium 85) и с имитацией Tizen/AVPlay, а не только в обычном браузере.
   И помнить: обычный браузер кэширует скрипты — перед проверкой правок сбрасывать кэш (иначе тестируется старый код).
7. Реклама — заработок byskaz: её пропуск только по явному выбору пользователя, по умолчанию выключен.
8. **Раскладка настроек.** Каждый новый пункт `addParam` попадает в `BS_SETTINGS_LAYOUT`
   (`src/loader.js`) в свой раздел и группу: Telegram — в Telegram, плеер — в плеер. Пункт вне раскладки
   попадает в «Обновление» и валит проверку тестом «настройки: все пункты модулей разложены по разделам».
9. **Сообщения канала ТВ.** Всё, что уходит между телевизорами, — через `busSend` (запечатывается ключом
   из токена) и принимается только через `busOpen`. Новый тип сообщения не добавлять в открытом виде.
10. **«Что нового» в окне обновления.** Пункты раздела версии в `CHANGELOG.md` уходят в `version.json`
   (`notes`) и показываются на ТВ в окне «Вышло обновление». Писать коротко, по-русски, без разметки.

## Выпуск новой версии
```bash
python tools/update_bundled.py      # только если на сервере новая Lampa — обновит встроенную копию и её hash
python tools/pack.py --bump         # поднять версию и собрать: dist/samsung-X.Y.Z.wgt + samsung.wgt
```
`CHANGELOG.md`: раздел версии должен начинаться строкой `## X.Y.Z — название`. По нему `pack.py`
берёт пункты для окна обновления (`changelog_notes`). Пункты — короткие, понятные пользователю.
Затем: запись в `CHANGELOG.md`, проверка (ниже), коммит в git.

## Проверка перед выпуском
- `pack.py` сам запускает автотесты (`node tests/run.cjs`) и проверяет манифест, ссылки index.html, совпадение встроенной
  копии с hash, пути архива. Новая логика — новый тест в `tests/run.cjs`.
- Chromium 85 (`%TEMP%\chromium85`) с имитацией Tizen по `file://`: Lampa загружается, ошибок нет, платформа `tizen`.
  Имитация — скрипт после `polyfills.js` в копии `src` (объекты `tizen.application` с `getRequestedAppControl`,
  `tizen.ApplicationControl(Data)`, `webapis.avplay`); запуск `chrome.exe --headless --remote-debugging-port=…` с user-agent
  Tizen 6.5, проверка через DevTools. Останавливать только этот процесс (по его `--user-data-dir`), не все `chrome.exe`.
- Встроенная копия: подменить адрес сервера на несуществующий — должна запуститься встроенная.
- Сторож: локальный «молчащий» сервер (порт 8790) + рабочий тестовый поток; сценарии — повисший поток → другое
  качество, нормальное видео без тревог, разовая ошибка без тревог, ошибка с остановкой, пауза, все качества висят.
  Внимание: в Chromium 85 (сборка с открытым кодом) нет H.264 — видео там не играет, сторожа проверять в обычном браузере.
- Серверы Skaz: юнит-тесты решений. С 1.7.61 автовыбор не трогает сервер ТВ by Skaz (`skaz_domain`), только
  серверы источников (`skazonline_servers`).
- Автообновление (с 1.7.63): подменить запомненный hash — уведомление «… обновится при следующем запуске», на экране
  перезапуска нет; Lampa ушла в фон (`visibilitychange`, hidden) — один перезапуск; в фоне с открытым плеером — нет.
  Новая версия функций берётся, только когда все её файлы есть на CDN (`update.js` → `verify`).
- Экран загрузки и уведомления: обычный запуск — только оригинальный экран Lampa, своих надписей нет (правило 1).
  Наша карточка — только при обновлении («Обновляю Lampa до …», уходит при `.lp-step`) и при ошибке запуска. Уведомления — карточка внизу по центру, ошибка —
  красной точкой. Смотреть в браузере в пропорциях ТВ (1280×720) с чистым кэшем.

## Значок
- `icon.png` — исходный значок пакета Skaz без изменений (512×423, PNG RGB; с 1.7.7). Свои варианты (1.6.0–1.7.5:
  круглый, квадрат, уменьшенный, сплющенный) не нужны: на ТВ 2016+ плитку рисуют `logo_appname_*` (ниже).
- Главная панель ТВ запоминает значок при установке: после смены значка старый может держаться до переустановки.
- **Плитка на главном экране ТВ 2016+** — из `logo_appname_bg.png` (фон, 1920×1080 RGB) и `logo_appname_fg.png`
  (белый логотип на прозрачном, 1920×1080 RGBA) в корне пакета — как в исходном пакете Skaz. 1.6.9 удалил их («для
  магазина») — ТВ 2022 после перезагрузки показывал запомненную плитку, а после запуска Lampa — серую заглушку.
  Вернули в 1.7.6; `pack.py` не соберёт пакет без них.
- С 1.7.8 всё, что касается значка, плитки и службы превью, — как в исходном пакете Skaz: `icon.png`,
  `logo_appname_*`, `service/service.js` (служба не завершается после `setPreviewData`) и блок `tizen:service` в
  config.xml (`auto-restart="true"`, `meta-key`). config.xml отличается от исходного только версией и привилегией
  `avplay`. 1.6.9 делал службу «по руководству Samsung» (выход после обновления, `auto-restart="false"`) — откатили.

## Эмулятор Samsung TV (Tizen 10.0)
- Tizen Studio в `C:\tizen-studio` (CLI: `tools\ide\bin\tizen.bat`, нужен Java 8), машина `lampa-tv`
  (`tools\emulator\bin\em-cli.bat launch -n lampa-tv`), `sdb` — `emulator-26101`.
- Подпись: профиль сертификатов Samsung `testtv` (автор + distributor с DUID эмулятора; для своего ТВ в distributor
  нужно добавить его DUID). Сертификат Tizen эмулятор ТВ не принимает.
  ```
  tizen package -t wgt -s testtv -- Lampa.wgt
  tizen install -n Lampa.wgt -s emulator-26101 -- <папка>
  tizen run -p 0SG81L944p.Lampa -s emulator-26101
  ```
- Пульт: `ecp-cli hmp "sendkey <клавиша>"` (up/down/left/right, ret — ОК, backspace — «Назад»). `sdb shell` у
  эмулятора закрыт; снимок экрана — только окном эмулятора (QEMU `screendump` пуст: картинка через GL).
- Журнал консоли: `python tools/pack.py --debug 10.0.2.2` (10.0.2.2 — это ПК, если смотреть из эмулятора) +
  `python tools/debug/logserver.py`. Для сценариев «плохой интернет / сломанный поток» в отладочную сборку добавляется
  тестовый скрипт после `polyfills.js` (поддельная скорость `bs_bw`, подмена адреса в `webapis.avplay.open`).
- Не проверить на эмуляторе: 4K/HDR/DRM, цветные кнопки пульта, ряд превью на главной.

## Отладка
- `python tools/pack.py --debug <IP ПК>` → `samsung-debug.wgt`: консоль, ошибки, все сетевые запросы, WebSocket и этапы
  Lampa уходят на ПК. Приёмник: `python tools/debug/logserver.py` (порт 8799, журнал `tools/debug/tv.log`).
- ТВ и ПК должны быть в одной сети. Если в большой сети адрес ТВ совпадает с другим устройством — поможет
  точка доступа на ПК (Windows раздаёт адреса `192.168.137.x`).
- `sdb` (Tizen Studio, `C:\tizen-studio\tools\sdb.exe`) подключается, только если в режиме разработчика ТВ указан IP
  этого ПК; одновременно может быть только одно устройство (ПК или телефон с установщиком).

## Установка
Пакет без подписи; установщик на телефоне подписывает его сам. Ставится поверх, настройки сохраняются.
С ПК — Tizen Studio и профиль сертификатов Samsung, в distributor которого есть DUID телевизора (см. «Эмулятор»).
Режим разработчика ТВ: «Приложения» → `12345` → включить, IP — устройства, с которого ставишь, перезагрузить ТВ.

## Известные ограничения
- Источники, которые висят ещё до плеера (RCH, `Origin: null`), пакет не лечит — сторож закроет плеер, выберите другой.
- Метки пропуска есть не для всех серий (их размечают зрители); главы — только для части фильмов.
- HD-трейлеры через `yt.skaz.tv` не подключены: видео и звук раздельно, AVPlay их не сводит.
- Быстрый старт убирает разбивку качеств из самого плейлиста (остаются качества от онлайн-плагина).
- «Качество под скорость интернета» узнаёт скорость только из просмотров (замеры AVPlay); у MP4 без остановок замер
  ничего не говорит о канале и не учитывается — пока нет замеров, качество не трогается.
- Старые ТВ (Tizen 2.4–5.x) на эмуляторе не проверить: Samsung выкладывает только образ Tizen 10.0.
